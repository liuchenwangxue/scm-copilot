# ADR-010：单库到读写分离的演进路径

- 状态：已采纳（W28 Day5 落地开关，B8 项 PoC 口径）
- 日期：2026-09-04（W28-D5）
- 相关：ADR-009（租户分片，同日入库）、`00_问题总清单` C7/B8
- 影响代码：`backend/app/shared/db.py`（路由开关）、`app/platform/settings.py`
  （`platform_ro_dsn`）、`app/main.py`（lifespan 接入 read factory）

---

## 一、背景与问题

平台库/业务库已分（alembic vs alembic_biz 双库），但**读写未分**——所有查询与写
操作共用同一 DSN。瓶颈（面试可讲"读了 ADR 才动手"）：

1. **读放大**：报表查询（daily_briefs 图表 / eval_reports / audit_logs 归档）与在线
   写（审批/会话/审计）共享连接池与 IO——报表慢查询会挤占在线请求的连接槽。
2. **扩展不对称**：读多写少的典型场景，MySQL 单主无法水平扩读（加只读副本是最廉价
   的读扩展手段，不需要改业务代码）。
3. **故障域**：无只读副本时，读请求故障与写请求同故障域——副本可隔离"读故障不拖垮写"。

## 二、决策：三级演进，本步到第二级（开关就绪）

| 级别 | 方案 | 特征 | 迁移成本 | 触发条件 |
|---|---|---|---|---|
| L1 | 单主（当前基线） | 读写同 DSN，连接池共享 | 零 | 默认 |
| **L2** | **读写分离（本 ADR 采纳）** | 读走只读副本 DSN，写恒走主；`DbRouter.dsn_for(op)` 路由 | 低（开关就绪，副本未上时零差异） | 单表 > 数千万行 或 读 P95 超过写 P95 1.5× 持续一周 |
| L3 | 拆库（B8 后续） | 按域物理拆多主（如 audit_logs 独立库） | 高（应用层事务拆分） | L2 后写侧仍到瓶颈，且读副本扩不动 |

> 触发阈值依据：读 P95 超过写 P95 1.5× 且持续一周——说明读负载已显著挤占在线写，
> 单主加副本的收益确定；否则副本只是增加运维面（复制延迟/故障域），不值得。

## 三、L2 实现（本项目落地，PoC + 开关）

### 3.1 路由开关（`shared/db.py`，纯逻辑零 IO）

```python
@dataclass
class DbRouter:
    write_dsn: str
    read_dsn: str = ""

    def dsn_for(self, operation: str = "read") -> str:
        if operation in READ_OPS and self.read_dsn and self.read_dsn != self.write_dsn:
            return self.read_dsn
        return self.write_dsn

    @property
    def has_read_replica(self) -> bool:
        return bool(self.read_dsn) and self.read_dsn != self.write_dsn
```

- **语义**：读操作且配置了有效副本 → RO DSN；其余（写 / 无副本 / 副本=主）→ 主 DSN。
- **本机无副本 → 零行为差异**（`read_dsn` 空或与主相同）：`make_routers()` 从 settings
  构造时默认空——部署只读副本前把 `SCM_DB_RO_DSN` 设为同主 DSN 即可预演路由逻辑，
  上线副本只改一个环境变量。

### 3.2 接入点（`main.py` lifespan）

- `app.state.session_factory` = 写 factory（现状不变，所有在线写路径主 DSN）。
- `app.state.read_session_factory` = 只读 factory（**仅** `has_read_replica` 时创建）；
  报表查询/NL2SQL executor 走 RO 的接入点（executor 已用 `biz_ro_dsn` 只读账号，
  本开关统一"读走 RO"路由语义）。

### 3.3 灰度与回退

- 开关即环境变量：副本未上 → `SCM_DB_RO_DSN` 空/同主 → 路由恒主，行为不变；
  副本就绪 → 填 RO DSN → 读请求自动切副本。
- 回退零成本：清空 `SCM_DB_RO_DSN` 或设回主 DSN，路由立即回到单主。
- 只读副本 DSN 建议用**最小权限账号**（仅 GRANT SELECT，与 NL2SQL `nl2sql_ro` 同哲学）。

## 四、影响与成本

| 维度 | 说明 |
|---|---|
| 性能 | 读请求剥离到副本 → 在线写连接池/IO 释放（读放大是主要收益） |
| 一致性 | 只读副本有复制延迟——**报表/归档类允许最终一致**；在线读写强一致的路径
  （审批/幂等/会话）恒走主，不受影响（路由按操作语义，不是全局随机） |
| 运维 | 新增副本管理面（复制状态监控）；本机/演示不启副本 = 零运维 |
| 代码 | 路由 20 行纯逻辑 + settings 1 个字段；调用方无感（不引入 session 级路由） |

## 五、未做/边界（诚实记录）

- **L3 拆库**：仅留演进路径，未实现——当前规模不需要；audit_logs 等大表独立库列三期。
- **session 级读写路由**：本版是"按操作类型路由 DSN"，未做"同一事务内读写自动路由"
  （那需要 SQLAlchemy 事件/上下文，复杂且易错）。现状：写路径全部主 DSN，读报表显式
  走 RO factory——清晰可控，无隐式行为。
- **复制延迟观测**：未接入主从延迟监控（`SHOW SLAVE STATUS`）；列三期运维项。

## 六、验证与证据

- 单测：`test_db_routing.py` 6 用例——读走 RO/写走主/无副本回退/同 DSN 无副本/别名
  语义/多库构造，纯逻辑 CI 可跑。
- 回归：全量测试绿；`make check`（ruff/mypy）0 error。
- 实测：本机无副本 → `make_routers().platform.has_read_replica == False`，lifespan
  不建 read engine，`/health` 行为与 W28-D1 完全一致（零行为差异实证）。

## 七、回退方案

清空 `SCM_DB_RO_DSN` 环境变量（或设为与 `SCM_PLATFORM_DSN` 相同）→ 路由恒回主 DSN；
`make_routers()` 默认构造即无副本语义，重启即回退，无数据迁移、无破坏性操作。
