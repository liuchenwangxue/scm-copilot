**目标**：AsyncMySaver 从"单连接串行"改"池化并发"——40 并发排队根因拔除。

**上午**：

2. 池化改造：
   ```python
   # 启动时建池（lifespan），Saver 持池不持连接
   pool = await asyncmy.create_pool(minsize=2, maxsize=10, host=..., port=3306, db="scm_platform")
   async def aput(self, ...):
       async with pool.acquire() as conn:
           async with self._saver_for(conn) as s:   # 每操作临时 Saver 或直接操作
               await s.aput(...)
   ```
   释放路径：`interrupt` 挂起后连接必须归还池（`finally` 里 release，杜绝泄漏）
3. 配置化：`SCM_CHECKPOINT_POOL_SIZE`（默认 10）进 `shared/config.py`；compose 里 MySQL 加 `--max-connections=300`（双实例 × 池 10 + SQLAlchemy 池 60，151 默认值会顶满）

**下午**：

**面试题 0.5h**：池大小怎么定？（Little's law：并发数 × 平均持有时长 / 1s ≈ 需求连接数；40 并发 × 50ms ≈ 2 条忙连接，池 10 是余量——能讲清"为什么 10 不是 40"）

### Day3（8/26 周三）★ 可靠性组件分布式化（A5–A8）

**目标**：熔断器/分布式锁/幂等/成本预算四个"单机缝隙"补齐，每条降级路径有单测。

**上午**：
1. 熔断器状态共享（A5）：
   - 本地保留 CLOSED 快路径（failure 计数在进程内）；阈值触发时写 Redis `cb:{name}` = OPEN（TTL=cooldown，10s）
   - 每请求先查本地缓存（1s stale 内不查 Redis）；OPEN 过期后任一实例探测成功 → 删键广播恢复
   ```lua
   -- 进入快失败：GET cb:{name}，存在且 TTL>0 → fast fail
   ```
2. 分布式锁 fail-open 兜底（A6）：Redis 挂 → 同 key 进程内 `asyncio.Lock()` 互斥 + metrics 计数器 `lock_local_fallback_total` + 日志 DEGRADED
   ```python
   except RedisDown:
       local = _LOCAL_LOCKS.setdefault(key, asyncio.Lock())
       async with local:
           return await fn(*a, **kw)
   ```
   注释写明边界：本地锁只防同进程并发，跨实例仍可能并发——高危写另见第 3 条

**下午**：
3. 幂等写路径 fail-closed（A7）：Redis 不可用时——**读类请求**（查询/生成）允许 sqlite 降级；**写类请求**（ops 高危工具执行）直接 403/503 拒绝，提示"幂等保护不可用"。判定函数：调用方声明 `risk="read"|"write"`
4. 成本预算 Redis 化（A8）：
   ```python
   spent = await redis.incrbyfloat(f"cost:{session_id}", tokens)
   if spent > limit: raise BudgetExceeded(...)
   ```
   Redis 挂 → 本地近似 + 日志（预算是软限制，fail-open 合理，写进 ADR 注释）
5. `test_reliability_matrix.py` 行为矩阵：4 组件 × {Redis 正常, Redis 挂} × {读, 写} = 16 格逐一断言（这是本周面试防御的核心证据表）

**面试题 0.5h**：熔断状态为什么不全放 Redis？（每请求一次 RTT 的延迟税；本地缓存+转变广播=秒级收敛，代价可接受——一致性级别的选择）

**验收**：16 格矩阵全绿；ops 高危工具在 Redis 挂时实测被拒；metrics 里能看到 fallback 计数。
**坑**：
- 熔断 Lua 里读 TTL 用 `TTL` 命令（-2 键不存在/-1 永生都要处理）
- fail-closed 的拒绝要给明确错误码（`IDEM_UNAVAILABLE`），别复用通用 500——SDK/前端要能区分"服务坏"和"保护拒绝"

### Day4（8/27 周四）★ SDK 0.2.0 + real 拆分（B1–B3）

1. SDK 自动重试（`sdk/scm_client/__init__.py`）：
   ```python
   def _request(self, method, path, *, max_retries=2, **kw):
       for attempt in range(max_retries + 1):
           try:
               return self._do(method, path, **kw)
           except ScmQuotaError as e:            # 429：尊重服务端节流
               if attempt >= max_retries or not e.retry_after or e.retry_after > 30:
                   raise
               time.sleep(e.retry_after)
           except (ScmServerError, httpx.TimeoutException):   # 5xx/超时：指数退避+抖动
               if attempt >= max_retries:
                   raise
               time.sleep(min(2 ** attempt + random.random(), 8))
   ```
