### Day4（9/3 周四）★ 多租户分片（C4/C5/B7 项）

**目标**：租户隔离从"payload 过滤"演进到"分片路由"，BM25 路隔离漏洞排查补齐。

**上午**：
1. 先堵 C5：排查 BM25 路租户过滤——`BM25Index` 的 chunk 元数据若无 tenant 维度则补：构建时 chunk 带 `tenant_id`，检索时先按租户过滤再打分（两租户语料交集实验证）
2. 分片路由（`shared/rag/sharding.py`）：
   ```python
   def collection_for(tenant_id: str, shards: int = 4) -> str:
       return f"kb_{zlib.crc32(tenant_id.encode()) % shards}"
   ```
   TenantFilter 改造：`retrieve()` 先路由 collection 再注入 payload filter（双保险保留——分片是性能隔离，filter 是正确性兜底）
3. ADR-009：记录"payload filter → collection 分片 → 独立实例"三级演进及触发条件（租户数 > X 或单 collection 点数 > Y）

**下午**：
4. 迁移脚本：现有单 collection 按租户哈希搬入 4 分片（uuid5 保持 point id，幂等可重跑）
5. 验证三件：`verify_isolation()` 分片模式下过；两租户并发检索性能对比（隔离语料更小 → 更快）；单分片删除文档不影响其他分片
6. 回归：KB 域全量测试绿（TenantFilter 接口不变，内部路由对调用方透明）

**面试题 0.5h**：租户隔离的三种层级及成本（payload filter 查询慢但零迁移；分片查询快但要路由层；独立实例最贵最干净——什么时候升一级：看 P95 与点数增长曲线）

**验收**：4 分片就位；BM25 双租户语料零交集；verify_isolation 绿；KB 回归绿。
**坑**：
- crc32 分布不均：4 分片 × 少量租户会倾斜——演示数据补足 12 租户验证分布（或直接说明并接受倾斜）
- 迁移期间新旧 collection 并存：开关 `SCM_SHARDING=on/off` 灰度，回退零成本
- Qdrant 分片 collection 的 HNSW 参数要一致（否则分片间召回率不齐）

### Day6（9/5 周六）★ Runtime PoC + 终验（C8/C9，B4 收尾）

**目标**：自研 agent loop 最小内核跑通 data 图（B5 PoC 口径），覆盖率冲 75%，混沌复验。

**上午**：
1. `shared/runtime/loop.py` 最小内核（~100 行，data 域同构）：
   ```python
   def run_graph(nodes: dict[str, Node], router: dict[str, Router], state: dict, max_steps:10):
       cur = "START"
       for step in range(max_steps):
           cur = router[cur](state) if cur in router else cur   # 条件边
           if cur == "END": return state
           nodes[cur](state)                                     # 节点改 state
       raise GraphLoopError(f"exceeded {max_steps}")
   ```
   - data 图 7 节点 + 3 路由函数搬上去（generate/validate/execute/repair/reject/format/degrade），mock 全链路跑通且结果与 LangGraph 版一致（同输入同输出对照测试）
   - ADR-011：记录"何时值得自研"（框架税：checkpointer/interrupt 生态绑定 vs 内核 100 行可控；结论=PoC 保留、kb/ops 留 LangGraph、混合运行）
2. 覆盖率收尾（B4 终验）：补 otel.py（连接失败路径）与 parser 洼地至总覆盖 ≥75%；确实难测的（纯网络壳）在报告里"文档化接受"清单列出

**下午**：
3. 混沌五连复验（快速版，脚本现成）：MySQL/Redis/Qdrant/LLM 超时/杀实例——重点看 D3 改造后的 redis-down 行为（幂等写拒绝、锁本地兜底）是否在演练中如预期
4. 全量回归 + 容器内 eval 复跑 + 压测 30 并发快验（W27 基线不劣化）
5. `reports/w28_report.md` 主体完成：两周全部前后对比汇总表

**面试题 0.5h**：框架抽象的税是什么？（隐式行为黑盒调试难、版本迁移风险、能力被框架上限锁死——PoC 证明"我随时能退出"就是解药）

**验收**：自研 loop 与 LangGraph 同构对照绿；覆盖率 ≥75%；混沌五连过；回归全绿。
**坑**：
- Runtime PoC 只迁 data 图——别贪心迁 ops（interrupt/checkpointer 生态是 LangGraph 主场，PoC 边界即 ADR 论点）
- max_steps 防环是底线（repair→validate→repair 死循环在自研内核里必须有熔断）
- 覆盖率最后 1pp 别硬凑——删死代码有时比写测试快（`rg` 找无引用函数）
