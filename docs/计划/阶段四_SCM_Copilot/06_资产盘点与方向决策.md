## 1. 执行摘要：三个判断

推荐以 **「SCM Copilot 供应链智能运营平台」** 作为融合项目——把 stage3-project-a（知识问答）与 stage3-project-b（业务操作）整合为一个**模块化单体生产平台**，在 90%+ 资产复用的前提下，集中补齐差距清单剩下的四项生产空白：**MySQL + NL2SQL、APScheduler 定时任务、SDK + Swagger 开放能力、真无状态多实例**。

1. **缺口清单已经把方向锁死。** 《生产技术差距清单》与《阶段四补充决策》共同指向：已闭环的是 Agent 编排、RAG、安全、可靠、观测；剩余空白集中在**数据侧（MySQL/NL2SQL）、调度自动化、开放生态**——这些只有在"做一个真实系统"时才能落地，单独练习没有载体。
2. **复用度决定成败。** A/B 两个项目已具备评测集、回归用例、部署编排、CI 流水线与量化指标（Hit@1 0.9038、工具成功率 99%、12/12 端到端验收）。新项目 = 平台化重组 + 三个新域，而不是从零开始。
3. **面试叙事从"两个应用"升级为"一个平台"。** "把两个 Agent 应用整合为生产级平台（数据迁移、无状态化、开放 API、调度自动化）"是 Java 出身转型者最能讲深的故事——同时命中架构、数据、运维三条面试主线。

| 关键数字 | 值 |
|---|---|
| 已有学习资产 | 22 周（W1–W22） |
| 代码与评测资产复用率 | 90%+ |
| 补齐的最后生产空白 | 4 项 |
| NL2SQL 执行准确率目标 | ≥0.80 |
| 双实例压测目标 | 40 并发 100% 成功 |

## 3. Harness 工程机制的映射

learn-claude-code 的价值不是"又学了一个框架"，而是一套**可迁移的机制清单**。新项目中每条机制都有落点，形成两个教程线的合流：

| Harness 机制（s01–s20） | 在 SCM Copilot 中的落点 | 状态 |
|---|---|---|
| s01–02 Agent Loop 与工具分发 | 统一工具注册表 + LangGraph 图分发（dispatch map 思想） | 继承 |
| s03 权限管线（直跑/审批/拒绝） | approval_gate 高危审批 + RBAC 中间件三态判定 | 继承 |
| s04 Hooks（Pre/PostToolUse） | 工具调用前后钩子：审计埋点、语义缓存失效 | 继承（W3 D18 落实物） |
| s05 TodoWrite 规划先行 | Planner-Validator 限次重规划（attempts≥2 防死循环） | 继承 |
| s06 子代理上下文隔离 | Orchestrator-Worker（Send 并行，子 Agent 只回传结果） | 继承 |
| s07–s10 按需加载与上下文压缩 | 语义缓存 + 长会话历史裁剪（超出预算时摘要化旧轮次） | W1 强化 |
| s12–s14 任务系统/后台任务/定时调度 | 调度域（APScheduler + MySQL job store）+ RQ 后台队列——正是本项目新增核心 | 新增 |
| s15–s18 团队协议与执行隔离 | 多域 Agent 协作边界：域间只经 API/事件通信，不共享内存状态 | W1 落地 |

## 5. 剩余生产缺口分析

以 2026-08-15 两份决策文档为基准（《生产技术差距清单》+《阶段四_生产技术缺口补充决策》），W21/W22 已补掉一大块，剩余缺口收敛为**「一主三次一深化」**：

| 缺口项 | 面试价值 | 工作量 | 现状与说明 | 归属 |
|---|---|---|---|---|
| **MySQL + NL2SQL** | ★★★ | 3–5 天 | 全库只有 SQLite（stage3-b biz_agent.db），无 MySQL、无 NL2SQL。数据分析/客服 Agent 高频考点，也是唯一需要"新域"的缺口。决策文档原话：最强面试点之一，建议作为项目 B 扩展——本计划将其升级为平台第三业务域。 | 第 2 周主攻 |
| **APScheduler 定时任务** | ★★ | 0.5–1 天 | 全库 0 命中。知识库自动更新、过期向量清理、审计归档、经营日报——"数据闭环自动化"的载体，低成本高叙事。 | 第 3 周 D13–D15 |
| **SDK 封装 + Swagger** | ★★ | 0.5–1 天 | /docs 已有，但无 pip 可安装 SDK 与 OpenAPI 规范化。"开放生态"是 Java 全栈最熟领域的低成本展示。 | 第 3 周 D16–D17 |
| **RBAC 落库（用户-角色-权限模型）** | ★★ | 1–2 天 | W21 已有 JWT + 三角色白名单，但是配置式；升级为 MySQL 持久化的用户-角色-权限三级模型是增量。 | 第 1 周 D2–D3 |
| **真无状态多实例** | ★★ | 1–2 天 | W22 双实例用 ip_hash 会话粘滞，属于"假水平扩展"；状态全外置（checkpointer/审批/会话）后换 least_conn 才是真无状态。 | 第 1 周 D5–D6 |

### 明确放弃项（沿用决策，写入项目 README 的"非目标"）

等保 2.0 加密、OCR/Whisper 多模态、钉钉/企微 IM、会议纪要/内网爬虫、LoRA 微调、多 GPU 调度、BI 图表生成、桌面客户端、人工坐席工作台、pyzipper 交付打包、行业多场景定制。

**面试话术（原策）**："这些不是不会，是按生产价值筛选后明确不做——单机 Agent 服务场景下 ROI 不划算，我把时间花在 NL2SQL/调度/开放 API 这类无论做什么项目都要有的基础设施上。"

## 6. 项目方向筛选

围绕"融进去所有已学技术 + 补齐生产空白 + 真实生产感"三个约束，构造四个候选方向：

### 候选卡

**A · SCM Copilot 供应链智能运营平台 —— 推荐**
把 A（知识问答）+ B（业务操作）整合为统一平台，新增数据分析域（NL2SQL over MySQL）与调度域，配管理控制台与开放 SDK。
- 优势：复用 90%+ 资产；四项空白全部覆盖；叙事升级为"平台化整合"；供应链场景与现有评测集延续
- 风险：整合期回归量大（靠 109 项旧用例兜底）；需克制 scope

**B · 企业 Agent 中台（Agent-as-a-Service）**
做底层平台：租户自建 Agent/知识库/工具，平台提供认证、配额、计费、监控。
- 优势：平台工程叙事完整；多租户/配额资产可复用
- 风险：无真实租户即"伪需求"；NL2SQL 等缺口不在主路径

**C · 垂直场景新产品（如客服/工单 SaaS）**
换新领域从零做一个 AI 产品。
- 优势：新鲜感强，可展示产品感
- 风险：抛弃供应链资产与评测集；时间耗在领域建模；产出"又一个 demo"，面试证据链断裂

**D · Coding/DevOps Agent 工具**
沿 learn-claude-code 线做代码审查/CI 助手类工具。
- 优势：Harness 机制学以致用；技术纵深好
- 风险：MySQL/NL2SQL/调度缺口不覆盖；与企业级数据叙事偏离；评测基准（SWE-bench 类）成本高

### 六维评分矩阵（1–5 分，权重均等）

| 评估维度 | A 平台融合 | B Agent 中台 | C 垂直新品 | D Coding Agent |
|---|---|---|---|---|
| 资产复用度（代码/评测/部署） | **5** | 3 | 2 | 2 |
| 生产缺口覆盖（四项空白） | **5** | 3 | 3 | 1 |
| 真实生产感（数据流/用户/运维闭环） | **4** | 2 | 3 | 3 |
| 面试叙事强度 | **5** | 3 | 3 | 3 |
| 时间可行性 | **4** | 2 | 2 | 3 |
| 技术纵深（有难度的核心问题） | **4** | 3 | 3 | 4 |
| **总分（满分 30）** | **27** | 16 | 16 | 16 |

> A 方向在复用度、缺口覆盖、叙事强度、可行性四维全面领先；D 方向仅技术纵深可比。

### 何时改选其他方向

若目标岗位明确是 **DevTools / AI Infra**（招 Coding Agent 工程师），D 方向权重应上调，可将本计划的 NL2SQL 域替换为"代码审查 Agent + 评测基准"域；若目标岗位是**平台/中间件**，B 方向可作为 A 完成后的二期演进（A 的多租户基座就是 B 的雏形）。**默认按 A 执行。**
