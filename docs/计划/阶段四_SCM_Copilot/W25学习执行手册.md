## 五、本周六问（Day1 快答 + Day7 复盘）

1. **规模**：六任务 cron 各一；24h 零重复观测；日报订阅 3 测试用户
2. **失败路径**：leader 锁 Redis 挂 → fail-open 全实例跑但任务幂等兜底（uuid5/日期键）；任务抛错 → job_runs 记 FAILED + 下轮重试，不影响调度器
3. **权限**：调度面板 `admin:*`；手动触发写审计；API Key 与 JWT 并存（机器身份 vs 用户身份）
4. **成本**：日报/夜间回归全走 mock（断言结构不断言语义）；real 日报演示 1 次
5. **部署**：无新增服务；APScheduler 随 backend 进程，双实例全跑
6. **数据闭环**：job_runs 表 → 面板可视化 → 失败率进 Grafana（W26 Day1）

## 六、七天计划

### Day1（8/31 周一）★ 调度基座

**目标**：APScheduler 骨架 + MySQL job store + leader 锁——任务"定义不丢、互斥执行、重启自动恢复"。

**上午**：
1. `platform/scheduler/__init__.py` 封装：
   - `AsyncIOScheduler(jobstores={"default": MySQLJobStore(...)})`
   - FastAPI lifespan：startup 时 `scheduler.start()`，shutdown 时 `wait=False` 优雅停
   - job 定义集中注册表（六任务名 → cron 表达式 → 回调），`misfire_grace_time=300` + `coalesce=True`（错过合并补跑一次）
2. `platform/scheduler/leader.py` 任务级互斥（复用 W19 锁实现改造成装饰器）：
   ```python
   def leader_lock(name: str, ttl: int = 300):
       async def deco(fn):
           async def wrapper(*a, **kw):
               owner = uuid4().hex
               if not await redis.set(f"lock:job:{name}", owner, nx=True, ex=ttl):
                   return SkipResult(f"{name}: another instance holds lock")
               try:
                   return await fn(*a, **kw)
               finally:
                   # owner 校验后释放（Lua 原子，防误删他人锁）
                   await release_if_owner(f"lock:job:{name}", owner)
           return wrapper
       return deco
   ```
3. `scheduler_job_runs` 写入：每任务执行记 `{job, status, started_at, finished_at, error, instance}`——零重复观测的依据

**下午**：
4. 单测：两实例并发触发同一任务（模拟）→ 一个执行一个 Skip；owner 校验（非 owner 释放无效）；TTL 过期后可重抢
5. 重启持久性：注册任务 → `docker compose restart backend-a1` → 任务定义与 `next_run_time` 完整（job store 在 MySQL）
6. `misfire` 验证：把系统时间场景模拟（或把 cron 改近触发验证补跑合并）

**面试题 0.5h**：Q5——APScheduler 多实例如何防重复执行？（调度器全实例跑高可用 + 任务级互斥 + 幂等键双保险，今天三层都亲手写了）

**验收**：重启后任务完整；互斥单测绿；job_runs 有记录。
**坑**：
- APScheduler 4.x 还是 alpha，锁死 3.x 稳定线
- `MySQLJobStore` 需要 `alembic`/`sqlalchemy` 同源依赖，和平台库 DSN 分开（`scm_platform` 内建表即可）
- 双实例同时 `scheduler.start()` 会对 job store 加锁初始化——APScheduler 自带 store 锁，别自己再加全局锁死锁

### Day2（9/1 周二）★ 数据闭环三任务

**目标**：知识库新鲜度 + 向量卫生 + 审计归档三个"运维自动化"任务上线。

**上午**：
1. `jobs/kb_increment_sync.py`（*/5min，本周最重要任务）：
   - docs 元数据表（stage3-a 已有）扫 `mtime > last_sync_ts` → 变更文档重切块重嵌入 → Qdrant upsert（uuid5(内容) 幂等）
   - 删除文档 → Qdrant 按 payload `source_doc_id` 删除向量
   - `last_sync_ts` 存 Redis（任务幂等键）
2. 增量验证流程：改一篇文档的一个段落 → 计时到 `/api/kb` 能检索到新内容

**下午**：
3. `jobs/vector_cleanup.py`（每日 03:00）：
   - 孤儿向量（payload 的 source_doc_id 已不在 docs 表）删除
   - 语义缓存过期键扫描（TTL 漏网 + 版本失效标记）
4. `jobs/audit_archive.py`（每月 1 日 04:00）：
   - 上月 `audit_logs` → `audit_logs_2026m08` 归档表（`CREATE TABLE ... AS SELECT` + 校验行数 + 删主表）
   - 归档批次号记 job_runs（幂等：批次已存在则跳过）
5. admin 面板 API：`GET /api/admin/scheduler/jobs`（状态/上次/下次）+ `POST .../jobs/{name}/trigger`（手动触发，写审计）

**面试题 0.5h**：KB 增量同步的幂等设计——uuid5 内容寻址 + last_sync_ts 水位，重复执行零副作用。

**验收**：改文档 ≤5min 可检索；删除文档向量同步消失；手动触发有审计；三任务 job_runs 正常。
**坑**：
- mtime 用 `>` 不用 `>=`（避免边界重复），水位更新在任务成功后（失败不推进）
- Qdrant 删除用 payload 过滤条件删除，别按 point id（增量拿不到 id）
- 归档任务先校验后删主表，两步间锁批次号防并发（虽然月跑一次，习惯要养）

### Day4（9/3 周四）★ OpenAPI 规范化

**目标**：API 从"能调"到"有契约"——文档即接口规范。

**上午**：
1. 三分组 tag：`chat / ops / data` + `admin`，每端点补 `summary + description + tags`
2. 统一错误码 schema：
   ```python
   class Err(BaseModel):
       code: str          # AUTH_401 / QUOTA_429 / NL2SQL_REJECTED / ...
       message: str
       trace_id: str
   ```
   所有 4xx/5xx 响应模型统一 `Err`；`app = FastAPI(responses={401: {"model": Err}, ...})`
3. 响应模型 100% 类型注解：chat 的 SSE 事件模型、nl2sql 的 `{table, sql, columns, rows}`、审批的 diff 结构

**下午**：
4. 端点覆盖自查脚本：遍历 `app.routes` 断言每条有 `summary` + `response_model`（或显式声明 streaming）
5. `/openapi.json` 导出 + 校验（`openapi-spec-validator`）；Swagger UI 过一遍人工验收清单：描述/参数示例/错误响应三要素
6. 版本化：`/api/v1` 前缀（现在上版本号成本最低，SDK 也好写）

**面试题 0.5h**：为什么坚持 OpenAPI 3.1 而非口头文档？（契约驱动：SDK 生成比对/前端 mock/集成方自助——Java 出身的天然优势面）

**验收**：`/openapi.json` 通过校验；端点覆盖 100%；Swagger UI 三分组可浏览。
**坑**：
- SSE 端点 response_model 写不了流式——显式 `response_class=StreamingResponse` + 文档里描述事件协议（四型事件）
- 错误码常量集中一个模块（`errors.py`），别散在各处字符串——SDK 侧要对齐同一套 code
- v1 前缀一上，CI 里旧用例的 URL 全要改（109 项里 httpx 直调的），预留 1h 批量替换
